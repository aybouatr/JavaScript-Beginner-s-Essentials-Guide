    # Node.js + C/C++ Native Addons

    ## What is a Native Addon?

    A **Native Addon** is a library written in **C or C++** that can be loaded and called from a **Node.js** application.

    Node.js uses **JavaScript** for application logic, but performance-critical code can be implemented in native languages.

    --- 

    ## Can Node.js Run C/C++ Directly?

    **No.**

    Node.js executes **JavaScript** (or TypeScript compiled to JavaScript).

    C/C++ source code must first be **compiled** into a native binary addon before Node.js can use it.

    ---

    ## Architecture

    ```text
    JavaScript (Node.js)
            │
            ▼
     Native Addon (C/C++)
            │
            ▼
     Operating System / CPU
    ```

    The JavaScript code calls functions inside the compiled C/C++ addon.

    ---

    ## Why Use Native Addons?

    Use C/C++ when JavaScript is too slow for CPU-intensive tasks.

    Examples:

    * Image processing
    * Video encoding/decoding
    * Audio processing
    * Compression
    * Cryptography
    * Physics simulations
    * AI / Machine Learning
    * Matrix multiplication
    * Scientific computing

    ---

    ## Benefits

    * Native execution speed
    * Access to existing C/C++ libraries
    * Better performance for heavy computations
    * Reuse legacy C/C++ code

    ---

    ## Drawbacks

    * More complex to build and debug
    * Must compile for each target platform
    * Requires knowledge of C/C++
    * Harder to maintain than pure JavaScript

    ---

    ## Node-API (N-API)

    Node-API is the official API for creating native addons.

    Advantages:

    * Stable across Node.js versions
    * Platform-independent
    * Recommended for new native addons

    ---

    ## Can I Use C Instead of C++?

    Yes.

    Node-API itself is a C API, and many projects wrap existing C libraries. In practice, many addons use C++ because it provides convenient wrapper libraries, but C code can be integrated as well.

    ---

    ## Is Node.js Written in C++?

    Mostly yes.

    Node.js itself is implemented primarily in C++ and uses several native libraries.

    Examples:

    * V8 JavaScript Engine → C++
    * libuv → C
    * OpenSSL → C
    * zlib → C
    * c-ares → C

    ---

    ## Typical Project Structure

    ```text
    Node.js Application
    │
    ├── JavaScript / TypeScript
    │   ├── Express / Fastify / NestJS
    │   ├── Routes
    │   ├── Business Logic
    │   └── Database Access
    │
    └── Native Addon (C/C++)
        ├── Image Processing
        ├── AI Algorithms
        ├── Compression
        └── High-Performance Calculations
    ```

    ---

    ## When Should I Write a Native Addon?

    Use a native addon when:

    * The task is CPU-intensive.
    * JavaScript performance becomes a bottleneck.
    * You need to integrate an existing C/C++ library.
    * You need low-level system or hardware access.

    Stay with JavaScript/TypeScript when:

    * Building REST APIs.
    * Handling HTTP requests.
    * Accessing databases.
    * Implementing authentication.
    * Writing general backend logic.

    ---

    ## Key Takeaways

    * Node.js applications are written in JavaScript or TypeScript.
    * C/C++ code cannot run directly inside Node.js; it must be compiled into a native addon.
    * Native addons are used only for performance-critical or low-level functionality.
    * JavaScript and C/C++ work together: JavaScript manages the application, while C/C++ accelerates specific tasks.

-----------------> How JavaScript Works Behind the Scenes? <-------------------

JavaScript is a single-threaded, interpreted (or just-in-time compiled) language that follows an event-driven, non-blocking concurrency model.

    1️⃣ Code Execution → JavaScript code runs line-by-line inside the engine (like V8).
    2️⃣ Call Stack → Keeps track of which function is currently being executed (LIFO).
    3️⃣ Heap (Memory) → Stores objects, arrays, and variables dynamically.
    4️⃣ Web APIs (Browser Environment) → Handle async operations like setTimeout, fetch, and DOM events. Functionalities provided by the browser, not by the JavaScript language itself. These are essential for asynchronous tasks. Examples: setTimeout(), fetch(), and the DOM (Document Object Model).
    5️⃣ Microtask Queue → Holds high-priority async callbacks like Promises and async/await.
    ➡️ These tasks are executed before anything in the Callback Queue.
    6️⃣ Callback Queue / Task Queue → Holds lower-priority async callbacks (like setTimeout, event listeners, etc.) waiting for the call stack to be free.
    7️⃣ Event Loop → Continuously checks the call stack; if it’s empty, it first empties the Microtask Queue, then processes the Callback Queue.

👉 Result: This architecture allows JavaScript to remain fast, efficient, and responsive, even with only one main thread of execution.


------------------------> Memory Management in JavaScript <----------------------

The Mark-and-Sweep algorithm is a core part of JavaScript’s automatic memory management, ensuring applications run smoothly without excessive memory usage. Understanding how it works internally helps developers write optimized and efficient code, reducing memory leaks and improving performance


Best Practices for Memory Management

    Always declare variables with let or const.
    Avoid using Global Variables as much as possible.
    Clear timers and intervals with clearTimeout / clearInterval.
    Remove event listeners when not needed (element.removeEventListener).
    Nullify references when an object is no longer needed (obj = null).
    Use WeakMap and WeakSet for objects that can be garbage-collected automatically.

Interconnections:

    Allocation → JavaScript reserves memory in stack/heap.
    Usage → Code runs and uses that memory.
    Garbage Collection → Automatically frees unused memory.
    Leaks → Prevent GC from working if references remain.


🛠️ Summary of Interconnections:

🔹 Stack → Stores primitives & function calls.
🔹 Heap → Stores objects, arrays, and functions.
🔹 GC → Frees unreachable memory automatically.
🔹 Best Practices → Help avoid leaks and keep apps fast.

-------------------> Introduction to Window, BOM, and DOM in JavaScript  <-------------------


    🪟 Window : The global container object in the browser that holds everything (BOM + DOM)
    🌐 BOM (Browser Object Model) : The browser environment (history, location, navigator, screen…) → Represents the browser environment around the page.
    🌳DOM (Document Object Model) : The structured representation of the webpage (HTML) → Represents the page content (HTML).

Hierarchy :

🪟Window
  ↳ 🌐BOM (browser features: navigator, screen, location, history, document)
  ↳ 🌳DOM (page structure, HTML content via document)

In summary, the window object is the top-level object in the browser environment. The BOM extends the window object to provide control over the browser itself, while the DOM is a subset of the BOM (accessed via window.document) that specifically deals with the content and structure of the web page.

Window → BOM + DOM

    Window 🪟 = The global container object.
    BOM 🌐 = Part of the Window, represents the browser environment (navigator, location, history, screen).
    DOM 🌳 = Also part of the Window, represents the web page content (document).

So the proper way to describe it is:
Window → BOM
Window → DOM


Interconnections Between Window, DOM & BOM


🔹 Window → The parent of everything.

🔹 BOM → Browser control system inside the Window.

🔹 DOM → Webpage structure inside the Window.

🔹 Both BOM and DOM are accessible via Window, but they serve different roles —
BOM for browser features 🧭, and DOM for page manipulation 🧱.

------------------------------------------> window.open() — Opening New Windows or Tabs <-----------------------------


Syntax:

    window.open(URL, name, specs, replace);

    Parameters:
    URL: The address of the page to open (optional). Default: blank page.
    name: A target name for the window/tab (e.g., _blank, _self, custom name).
    specs:A string defining window features (size, position, scrollbars, etc.).
    replace: Boolean (optional). If true, replaces the current history entry.
